# Layout A (Tool Grid) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the text-list homepage with a filterable grid of icon cards, and give every tool page a centred icon header and, for file tools, one big button in place of the dashed drop box.

**Architecture:** Lucide icon markup is copied once into `src/icons.ts` and drawn by an `Icon.astro` component. A `ToolCard.astro` component is shared by the homepage grid and the Related tools list. The homepage gets a wider container and a chip filter in an inline script. The tool-page changes are CSS on the existing `.drop` markup plus a header in `ToolPage.astro`, so no tool component's logic or markup changes.

**Tech Stack:** Astro 7 static build, vanilla TS/inline JS, CSS in `src/styles/tokens.css`, Vitest (build-output tests), Playwright (e2e).

**Spec:** `docs/superpowers/specs/2026-10-24-layout-a-design.md`

## Global Constraints

- Every tool page loads at most 15 KB of gzipped JS before a file is dropped (`npm run check:budget`).
- No new runtime dependency and no new network request: icons are inline SVG in the HTML.
- `lucide-static` is pinned exactly at `1.52.0`, as a devDependency (it only supplies licence text and the drift check).
- Colours come only from the existing tokens (`--accent`, `--tint`, `--tint-strong`, `--edge`, `--line`, `--ink`, `--ink-muted`), with no shadows or gradients.
- Touch targets are at least 40 px for chips and 64 px for the main file button.
- Copy: no new strings except the chip labels `All`, `Image`, `PDF`, `AI`, `Video`, `Developer`.
- The existing e2e suites (all except `home.spec.ts`) pass **unchanged**. Editing one means the restyle reached logic: stop and fix the restyle.

## Spec amendment (needs the product owner's OK at plan review)

Spec section 4 adds an "or drop files here" line under the button. Instead, this plan moves each zone's existing `.drop-title` ("Drop a PDF here", "Drop a photo here", "Drop a video here", …) below the button with CSS `order`, styled as the muted hint. That gives the same hint in each tool's own words, needs no markup change to the four tool components, and keeps the drag target unchanged. Below 720 px the title is hidden, as it is today.

## Review Focus

1. **The longest card names on a 2-column phone grid** ("Base64 encode and decode", "WebP to JPG or PNG") wrap inside the card without making the page scroll sideways. Test in Task 2.
2. **Keyboard use of the chips:** Tab reaches each chip, Space/Enter presses it, `aria-pressed` follows, and the focus ring is visible. Test in Task 2.
3. **No JavaScript:** the chips stay hidden and all 17 cards show. Test in Task 2 (built HTML).
4. **The drag-over state still reads as a drop target:** with `.is-over` the zone shows the dashed `--edge` border and `--tint-strong` fill. At rest there is no border. Test in Task 4.
5. **The privacy line stays visible under the big button** on every file tool at both widths. Test in Task 4.
